## 2. Real-World Retrieval Regression Audit & Calibration

### 2.1 The Phase 9 Regression
In the initial Phase 9 benchmark (`a1e41a3`), `real_world_flask_subset` exhibited a sharp regression where Hybrid retrieval performed worse than Vector-only retrieval:
- **Vector-Only**: Precision@1: **45.45%**, MRR: **0.6818**, nDCG@5: **0.6494**
- **Hybrid (Pre-calibration)**: Precision@1: **27.27%** (-18.18%), MRR: **0.5606** (-0.1212), nDCG@5: **0.5661** (-0.0833)

### 2.2 Root-Cause Identification
A deep technical audit revealed four compounding structural defects:
1. **Single-Word CamelCase Symbol Extraction Gap**:
   - `QueryAnalyzer` regex `CAMEL_CASE_PATTERN = r"\b([A-Z][a-z0-9]+(?:[A-Z][a-z0-9]+)+)\b"` strictly required multiple humps (`UserAccount`).
   - Single capitalized class names (`Flask`, `Config`, `Scaffold`) were ignored, failing to detect `QueryIntent.EXACT_SYMBOL`.
2. **Premature Graph Traversal Execution**:
   - When candidate symbols were empty, `HybridRetriever` grabbed vector top hits (`make_config`) and executed `graph_service.find_callers("make_config")` because line 196 had `if "callers" in plan.graph_operations or not plan.graph_operations:`.
   - Structural caller traversal polluted semantic and configuration queries with irrelevant callers.
3. **Pseudo-Graph BM25 Duplication in RRF**:
   - `HybridRetriever` ran BM25 searches for graph symbol names and injected them into `graph_results`.
   - In Reciprocal Rank Fusion, the same chunks were counted twice across Keyword and Graph lists, artificially inflating irrelevant entities.
4. **Extreme Strategy-Specific Weight Skew**:
   - `weights["GRAPH"] = 1.8` while `weights["VECTOR"] = 0.7` excessively penalized high-confidence vector matches.

## 4. Technical Audit of Citation & Intelligence Metrics

### 4.1 Citation Validity & Claim-Level Coverage
- **Offline Benchmark Implementation**: In `backend/evaluation/benchmark_orchestrator.py`, answers were synthesized directly from retrieved code chunks using verified metadata templates (`"The symbol '{r.symbol_name}' is declared in [{r.file_path}:{r.start_line}-{r.end_line}]."`).
- **Audit Assessment**: This tests the citation extraction and validation logic (`calculate_line_overlap_iou()`, range bounds verification) with mathematical rigor (100% validity and coverage). However, it does not evaluate live LLM hallucination rate. Live generation is independently evaluated in Phase 7 integration suites (`tests/evaluation/test_grounding_evaluation.py`) where Gemini generates answers against retrieved chunks.

### 4.2 Adversarial Prompt Injection Defense
- **Offline Benchmark Implementation**: Evaluates deterministic detection of known injection markers (`SYSTEM_PWNED_1234`, `LEAKED_KEY_XYZ`) within pre-sanitized generated text.
- **Audit Assessment**: Confirms that if a model echoes an injection marker, the validator detects the breach. True adversarial robustness requires live prompt evaluation against frontier LLMs.

### 4.3 Bug Investigation & Impact Analysis
- **Offline Benchmark Implementation**: Evaluated against labeled synthetic AST fixtures in `synthetic_auth_repo` (`process_payment` with unresolved calls, `delete_account_endpoint` with empty except clauses).
- **Audit Assessment**: Yields 100% precision and recall on static AST-detectable structural defects. It does not generalize to runtime logical bugs, race conditions, or dynamic reflection.
