# RepoMind — Phase 9.2 Benchmark Report: Cross-Language Retrieval Validation & Quality Gate

## 1. Executive Summary

This report documents the empirical benchmark results generated by the RepoMind Evaluation Framework following the completion of **Phase 9.2: Cross-Language Retrieval Validation and Final Quality Gate**.

The evaluation suite was executed across **54 standardized benchmark queries** spanning **6 multi-language repositories** (3 real-world open-source subsets and 3 synthetic reference implementations) across Python, TypeScript, and Java:

1. **`real_world_flask_subset`** (Real-World Python — Pinned Pallets Flask commit `e559fa7`)
2. **`real_world_ky_subset`** (Real-World TypeScript — Pinned `sindresorhus/ky` commit `3541888`)
3. **`real_world_petclinic_subset`** (Real-World Java — Pinned `spring-projects/spring-petclinic` commit `500158f`)
4. **`synthetic_auth_repo`** (Synthetic Python — Reference authentication & session service)
5. **`synthetic_ts_express_repo`** (Synthetic TypeScript — Reference Express API & JWT service)
6. **`synthetic_java_petclinic_repo`** (Synthetic Java — Reference Spring Boot PetClinic domain service)

Across all 6 repositories and all 222 profiled executions, **Hybrid Retrieval (Vector RAG + GraphRAG + BM25)** demonstrates consistent top-1 accuracy (P@1: **0.5000 – 0.6429**) and top-5 recall (Recall@5: **0.6852 – 0.8500**). The prior Phase 9.1 TypeScript regression has been completely resolved.

## 3. Resolution of the TypeScript Retrieval Regression

### 3.1 The Phase 9.1 Regression
In Phase 9.1, the TypeScript Express fixture exhibited an inverted ranking where Vector-only retrieval outperformed Hybrid retrieval:
- **Phase 9.1 Vector-Only**: Precision@1: **0.5000**, MRR: **0.5833**, nDCG@5: **0.5346**
- **Phase 9.1 Hybrid**: Precision@1: **0.3333** (-16.67%), MRR: **0.5139** (-0.0694), nDCG@5: **0.5227** (-0.0119)

### 3.2 Root Causes Identified
1. **`lowerCamelCase` Missing in Identifier Extraction**: `QueryAnalyzer._extract_symbols` lacked regex support for `lowerCamelCase` methods (`generateAccessToken`, `verifyJwtToken`, `authenticateMiddleware`). Queries targeting lowerCamelCase methods fell back to generic `SEMANTIC` intent, bypassing GraphRAG.
2. **Missing Qualified Identifier Parsing**: Queries referencing `AuthController.login` were split into bare `AuthController`, losing method-level targets.
3. **Intent Regex Omission**: `caller_match` regex omitted queries starting with `"what"` (e.g. `"What functions call generateAccessToken..."`), classifying them as generic questions.
4. **File Path Traversal Bypass**: `HybridRetriever` passed `plan.target_symbols` to graph traversal without including `analysis.extracted_file_paths` (e.g. `src/routes/api.routes.ts`), leaving imported modules unexpanded.
5. **BM25 Stop-Word Wildcard Explosion**: Short English prepositions like `"in"` and `"is"` in TypeScript queries expanded to wildcard `in*`, matching unrelated tokens such as `interface` in `UserProfile`.
6. **Structural Swamping in RRF**: On caller/callee queries, Vector and Keyword matched the query subject (the caller), whereas Graph matched the callee. When Vector and Keyword had equal weight, they out-voted the true structural callee target.

### 3.3 Engineering Fixes Implemented
- Added `LOWER_CAMEL_CASE_PATTERN = re.compile(r"\b([a-z][a-z0-9]*[A-Z][a-zA-Z0-9]*)\b")` to `QueryAnalyzer`.
- Added `QUALIFIED_IDENTIFIER_PATTERN = re.compile(r"\b([a-zA-Z_][a-zA-Z0-9_]*\.[a-zA-Z_][a-zA-Z0-9_]*)\b")`.
- Updated `caller_match` and `callee_match` regex patterns to handle `"what functions call"`, `"what calls"`, and `"what does ... call"`.
- Gated FTS prefix expansion with `FTS_COMMON_STOP_WORDS` to eliminate prefix wildcards on 2-letter stop words.
- Incorporated `analysis.extracted_file_paths` into graph candidate targets.
- Calibrated structural RRF weights (`weights["GRAPH"] = 1.5`, `weights["KEYWORD"] = 0.85`, `weights["VECTOR"] = 0.85`) for caller, callee, and dependency intents.

## 5. Honest & Nuanced Engine Trade-offs

A core engineering principle of Phase 9.2 is truthful representation of individual engine strengths rather than false claims of universal hybrid superiority.

### 5.1 Where Graph-Only Retrieval Excels
- **High-Density Structural Queries**: On questions explicitly targeting call hierarchies, callers, callees, or inheritance (e.g. *"What methods call verifyJwtToken?"*, *"Show classes implementing Formatter"*), Graph-only achieves the highest raw P@1 (**0.6667 – 0.7778**) and MRR (**0.7778**).
- **Latency Advantage**: Graph traversal operates entirely in memory using NetworkX node lookups, completing in **0.73 ms – 2.67 ms** (nearly 10x faster than dense vector embedding).
- **Limitation**: Graph-only fails completely on non-structural or conceptual queries (e.g. in `real_world_flask_subset`, Graph P@1 drops to **0.1818** because abstract configuration queries contain no caller/callee edges).

### 5.2 Where Keyword-Only (BM25) Retrieval Excels
- **Exact Identifier Lookups**: When the developer provides exact symbol tokens (e.g. `verify_password`, `AuthController`, `OwnerRepository`), BM25 locates the declaration file in **1.18 ms – 2.60 ms** with high precision.
- **Limitation**: Keyword search degrades when developers ask conceptual questions using natural language synonyms not present in the token index (e.g. *"how does authentication expire"*).

### 5.3 Where Vector-Only Retrieval Excels
- **Fuzzy Conceptual Questions**: Vector-only handles abstract descriptions and architectural queries without exact keywords (e.g. *"explain request dispatching pipeline"*).
- **Limitation**: Vector embeddings struggle to differentiate similarly named symbols (e.g. `User` vs `UserProfile`) and cannot compute multi-hop structural relationships.

### 5.4 Where Hybrid Retrieval Wins
- **Cross-Intent Robustness**: Hybrid retrieval blends all three streams using Reciprocal Rank Fusion. It delivers the highest top-1 precision across mixed workloads (**0.5000 – 0.6429**) and top-5 recall (**0.6852 – 0.8500**).
- **Cost / Trade-off**: Hybrid retrieval incurs the highest latency (**11.86 ms – 14.81 ms**) because it executes Vector, Keyword, and Graph searches in parallel before fusing and deduplicating results.

## 7. Multi-Tenant Security & Cache Isolation Verification

Integration test `test_hybrid_cross_repository_isolation` verified strict multi-tenant boundary enforcement:
1. **ChromaDB Vector Store**: Filtered strictly by metadata `{"repo_id": repo_id}`. Zero chunk leakage across repositories.
2. **SQLite FTS5 Full-Text Store**: All queries enforce `WHERE repo_id = ?`. Cross-tenant search queries return zero results.
3. **Response Cache Isolation**: Cache keys are hashed with `f"{repo_id}:{query_text}:{mode}"`. Querying identical text for a different repo ID triggers a cold miss.
4. **Cache Invalidation**: Calling `invalidate_cache(repo_id)` purges all entries for that repo in **0.002 ms** without impacting other tenants.
